# superset-patches

Bind-mounted patches applied to the official `apache/superset:3.1.0` image.

Each file here overlays the same path inside `/app/superset/static/assets/` in
the running container via a volume mount in `docker-compose.yml`.

## Files

### `3871.c687a6d83eaaee71a216.entry.js`

Three edits to the plugin-chart-echarts bundle:

1. Grid right margin widened from `7*l.gridUnit` (28 px) to `18*l.gridUnit`
   (72 px) so the last X-axis tick label (and any right-edge legend overflow)
   renders inside the chart canvas. Applied 2026-05-11.
2. `legendTopRightOffset:55` → `legendTopRightOffset:115` (applied
   2026-08-17). On zoomable charts the top legend (scroll pager with its
   ~50 px invisible hit-rect, plus the All/Inv selector buttons) crowded the
   toolbox "zoom area"/"restore zoom" icons, stealing their clicks. The
   bigger offset gives the icons clear airspace.
3. WM-ZOOM-SLIDER-RED (applied 2026-08-18). Both dataZoom slider literals
   (Timeseries + Mixed Timeseries transformProps) wrapped in Object.assign
   that merges the WinAir brand-red slider style (#CD1F25 handles,
   rgba(205,31,37,0.12) filler, red selectedDataBackground -- same recipe as
   LatestPricesPanel.tsx zoomSliderStyle) ONLY when location.pathname matches
   the WM dashboard: embedded uuid 36365808-d276-44ea-8cc7-e305e2bb9718 or
   /superset/dashboard/6/. All other dashboards keep stock ECharts blue.
   Grep marker: WM-ZOOM-SLIDER-RED (2 occurrences). Verified headless via
   wmslidertest.js (dash 6 red, dash 1 stock).

- **Scope**: every ECharts time-series chart in every Superset dashboard in
  this install.
- Both are exact-match single-occurrence string replacements.

### `8755.b325fab1a4b5f24a84fc.entry.js` (echarts core/vendors)

"Restore zoom" fallback (applied 2026-08-17). The toolbox back button pops
an internal zoom-history stack; after any notMerge `setOption` rebuild the
stack references destroyed dataZoom component ids, so the pop is empty and
the button silently does nothing. Patch: in the toolbox feature's
`_dispatchZoomAction`, an empty batch now dispatches a full-range reset
(`dataZoomIndex:0, start:0, end:100`) instead of no-op. Normal multi-step
zoom undo is unchanged when history is valid.

- Exact match on
  `t.length&&this.api.dispatchAction({type:"dataZoom",from:this.uid,batch:t})`
  (single occurrence), replaced with a ternary adding the fallback dispatch.

### `*.chunk.js` (14 files — Echart wrapper copies)

Zoom-persistence patch (applied 2026-08-17). Superset's Echart wrapper calls
`chart.setOption(options, /*notMerge*/ true)` on every re-render, wiping the
user's dataZoom window back to 0–100 (visible as "zoom instantly resets" on
dashboards). Webpack duplicated the wrapper into 14 per-viz chunks; each got
the same guarded edit: snapshot `getOption().dataZoom` before `setOption`,
and if a non-default window existed and the new option still has a dataZoom,
re-apply it via `dispatchAction({type:"dataZoom", dataZoomIndex:0, ...})`.
All wrapped in try/catch — on any error behavior is exactly stock.

Generated by `make_zoom_patches.py` (in this directory), which finds the
single `REF.current.setOption(OPT,!0))}),[` occurrence per file and rewrites
it. Re-run it after an image upgrade (update the chunk-hash list first —
find the files with `grep -l zrEventHandlers /app/superset/static/assets/*.js`).

### `wmslidertest.js`

Headless check for the WM-ZOOM-SLIDER-RED patch: loads a dashboard, digs the
ECharts instances out of the React fiber, prints each slider dataZoom's
fillerColor/handle color. Run like zoomtest.js (below); TARGET env overrides
the dashboard URL (default dash 6; use dash 1 as the stock-styling control).

### `zoomtest.js`

Headless Playwright verification for the zoom fixes. Run on the docker host:

```bash
cd ~/CPI/superset-patches && docker run --rm --network host \
  -v $PWD:/test -w /test -e PLAYWRIGHT_BROWSERS_PATH=/ms-playwright \
  mcr.microsoft.com/playwright:v1.44.0-jammy sh -c \
  'npm init -y >/dev/null; PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm i --silent playwright-core@1.44.0 >/dev/null; node zoomtest.js'
```

Checks: legend gap = 115 px, icon click activates crosshair, drag zooms,
zoom survives notMerge rebuilds, restore resets to 0–100.

## Upgrading Superset

The chunk filename includes a content hash that changes between Superset
versions. After upgrading the image:

1. **Temporarily comment out** the bind mount line in `docker-compose.yml`
   so the unpatched image asset is exposed.
2. Recreate the container so the new image's assets are visible:
   `docker compose up -d --force-recreate superset`
3. Find the new chunk:
   ```bash
   docker exec cpi-superset-1 grep -l "right:7\\*l.gridUnit" \
     /app/superset/static/assets/*.js
   ```
4. Apply the same edit to that file:
   ```bash
   docker exec cpi-superset-1 sed -i \
     "s|right:7\\*l\\.gridUnit|right:18*l.gridUnit|" <new_file>
   ```
5. Copy the patched file out:
   ```bash
   docker cp cpi-superset-1:<new_file> ./superset-patches/<new_hash>.entry.js
   ```
6. Update the bind mount path in `docker-compose.yml` to the new filename
   on both sides of the `:` and uncomment.
7. `docker compose up -d superset` to re-mount.

If the upstream code structure changes (no longer `7*l.gridUnit`), the
pattern match in step 3 will return no results — in that case, inspect the
new chunk's `grid:{...}` literals and find the analogous right-margin value.

The same re-derive procedure applies to the zoom patches: after an upgrade,
re-find the plugin chunk (`legendTopRightOffset`), the core chunk
(`dataZoomSelectActive`), and the wrapper chunks (`zrEventHandlers`), apply
the edits documented above (`make_zoom_patches.py` automates the wrapper
ones), update the compose mounts to the new hashes, and re-run `zoomtest.js`.
